Google Search Ranking & Discoverability Capstone

A leakage-aware machine learning workflow for ranking content that may need human review for possible performance decline.

Research question:
Can February 2026 content-performance signals be used to identify and rank content that may need review for possible decline in March 2026?

Decision supported: Which content should a human SEO or content reviewer inspect first?

1. Title + Abstract

Abstract

This study asks whether February 2026 content-performance signals can be used to rank content for possible performance-decline review in March 2026. A Logistic Regression model was trained using February-only performance features and evaluated with a client-grouped 80/20 validation split so that test clients were unseen during training. The study-specific decline label was defined as March clicks being lower than February clicks, while March data was used only for outcome construction and not as a model feature. On the grouped test set, the Logistic Regression model achieved 0.8782 accuracy compared with 0.8794 for the majority-class baseline. The result is therefore treated as a directional decision-support experiment for prioritizing human review rather than evidence that the model guarantees future decline or predicts Google's ranking algorithm.

2. Introduction / Problem Statement

Content teams often have more pages to review than they can manually inspect. A useful machine learning workflow can help organize that review by ranking content according to measurable historical performance signals.

This project focuses on a specific operational decision:

Which content should a human SEO or content reviewer inspect first?

The analysis uses February 2026 performance information to construct a ranking signal for a March 2026 decline-review task. The objective is not automatic publishing, deletion, redirection, or a claim about Google's internal ranking system.

The final output is a ranked review queue containing a model score, reason codes, and a suggested human-review action.

4. Methodology

Feature construction

February performance variables were aggregated from the daily warehouse records to one client-content modeling row.

Model

A Logistic Regression classifier was trained using standardized February-only features.

Baseline

The baseline predicts the majority class in the validation set. This provides a simple reference point against which the model can be evaluated.

Validation design

The primary evaluation uses a client-grouped 80/20 split. Forty clients were used for training and ten previously unseen clients were used for testing.

Leakage checks

The final feature vector contains no March outcome variables, no future-derived fields, and no decision-derived flags.

A deliberate leakage experiment added March clicks to the feature vector. That intentionally contaminated model achieved approximately 0.9998 accuracy, demonstrating that future outcome information could create an artificially strong result.

Leakage decision: March clicks were deliberately excluded from the production feature vector. The 0.9998 leakage result is not treated as a valid model result.
Methodology audit: PASSED.

Why the validation design matters

An earlier row-based split produced a Logistic Regression accuracy of 0.9627. The client-grouped result fell to 0.8782, while keeping test clients completely unseen during training.

This difference suggests that the row-based result may have been optimistic because observations from the same clients could appear on both sides of the split.

The grouped result is therefore used as the primary and more conservative evaluation for this capstone.

6. Limitations & Honest Framing

  1. Study-specific label: Decline is defined specifically as March clicks being lower than February clicks. It is not a universal definition of content decay.
  2. Model does not beat the grouped baseline: The Logistic Regression accuracy of 0.8782 is slightly below the majority baseline of 0.8794.
  3. Row-split performance was optimistic: The 0.9627 row-split accuracy should not be treated as the primary generalization estimate.
  4. Observational analysis: The results show measured associations in this dataset and do not establish that a particular content change causes improved search performance.
  5. Single feature/outcome window: February-to-March analysis provides a limited temporal view and may not generalize to other periods.
  6. Feature coverage: The model uses a defined set of performance features and does not represent every possible content or search signal.
  7. Human review is required: The ranked queue is a prioritization aid, not an automated publishing system.
  8. No Google algorithm claim: The analysis does not predict Google's ranking algorithm and does not claim that refreshing a page will cause a ranking improvement.
Honest framing: The output should be interpreted as measured, directional, decision-support information for prioritizing content review.

Final Takeaway

The capstone demonstrates a complete machine-learning workflow from question framing and warehouse data preparation through leakage-aware validation and ranked content recommendations.

The most important measured result is that the client-grouped Logistic Regression model achieved 0.8782 accuracy compared with 0.8794 for the majority-class baseline.

Rather than overstating this result, the project treats the model as a directional decision-support experiment that can help organize human content review. The workflow also demonstrates why grouped validation and strict future-information exclusion matter when evaluating models on repeated client-level data.
